# 近 30 天模型上新采集规则

用于维护模型上新证据，并由 `site/data/models.json` 生成「近期上新」近 30 天派生视图（首页使用近 7 天正式发布事件）。跨模块 ID 和字段约定见 [`model-data-contract.md`](model-data-contract.md)。

## 范围

- 底层六类保持原数据值；界面统一视频、图像、大语言模型、音频四类，音频子类为音乐生成、语音、综合音频。
- 不收智能体工具版本、普通产品功能、接口参数、榜单变化或仅有新闻转述的未确认项目作为正式模型发布。
- 时间范围为采集日往前 30 天，按厂商实际发布日期判断；首页更新日期、新闻转载日期和再次推荐日期不能替代正式发布日期。
- 近期窗口以外的旧型号不为填满列表而补入。无官方新型号时允许结果为空。

## 核验与记录

1. 每日先检查 AI Hub（https://aihub.com/briefing）和已采集的 AIHOT、橘鸦简报，用于尽早发现候选项；这些聚合来源不作为发布日期、型号名称或发布状态的最终证据。
2. 每条记录须有可打开的厂商官网公告、官方模型卡、官方文档或官方仓库链接。优先公告；模型卡更新只有在确认是新型号后才收录。官网若为客户端渲染、自动采集器未读到内容，应打开页面人工核验，不要把零匹配当成没有发布。
3. 逐项核实正式名称、类别、发布日期和可用/权重状态。明确标注「计划开源，尚未发布」等限制，不把计划说成已开放。
4. 同一模型去重；同家公司同批发布多个型号可以在页面上按公司合并展示，数据仍逐型号保留。
5. 不确定或找不到官方证据的内容不进入数据，并在当日日更中说明未核实项。不得推测版本号。
6. 通过 `scripts/build_model_release_digest.py` 重新生成窗口和条目，不直接手改生成文件。

新型号应先在权威模型目录中创建版本，并写入官方证据、正式发布日期和可用状态；同批公告的多个型号逐个绑定自己的版本 ID。模型卡更新可作为证据来源，但若只是能力、接口或功能变化，不创建新模型上新条目。

## 页面语义

近期上新分正式发布、待复核、官方公告三个模式，7/30 天切换。已核实服务上线（verifiedStages）只在官方公告呈现，不计入首页或正式发布数；待复核也不计数。首页四项指标仅统计正式发布事件，禁止附加上线数字。页面按公司汇总近期条目，以横向铺满的行卡展示发布日期、类别、型号、中文摘要、可用状态和官方原文链接。它不是完整行业发布记录；缺少条目代表当前采集证据不足，不能据此断言该厂商没有发布。


## 信源发现治理（2026-11-26）

- 持续发布目录和 RSS 优先，单篇历史发布文章仅作为核验依据；停用 Pika H3 Flex 和 Luma 固定旧版本监控，保留历史记录。
- OpenAI 新闻 RSS 覆盖 GPT 与 GPT Image；Vidu 匹配未来 Q 系列；Qwen 统一新闻目录覆盖语言、图像及音频；新增 Anthropic、Google Gemini、DeepSeek、PixVerse、ElevenLabs、xAI、Mureka、Midjourney、Kimi、MiniMax 等官方发现入口。
- HTTP 成功但无匹配项单独标记 zero-match；不能据此断言没有新消息。仅采集成功也不能证明日期和型号准确。
- 官方目录的自动发现属于待核验数据；不从邻近的导航或图片链接猜测文章 URL。
- 新信源须经过 GitHub Actions dry-run 测试，未读到数据的来源需继续排查；不将公开页面可访问等同于解析成功。

- 第一轮真实探测（2026-11-26，Actions 45762129173）：25 个启用源，24 个请求/解析未抛错，18 个有匹配、6 个零匹配、1 个 RSS 解析失败；43 个新发现 ID（含旧消息和产品更新，不能称为新模型数）。Midjourney RSS 随后改为官方 HTML 更新目录；新增阿里云新模型目录、Niji 官方博客与腾讯混元产品动态。Mureka 改按模型卡/更新表读取；修正 Meta Muse 的规范家族 ID。
- 官方信源健康折叠区展示实际持久化快照的检查时间、异常、零匹配与最近成功时间；超过两小时提示延迟。配置覆盖率只反映家族与采集规则的关联，不是实际召回率。


## 第三轮信源修复

- Google 增加官方新闻 RSS 与 DeepMind 博客，模型卡支持标题备用解析。Qwen 图像补充官方仓库 News；腾讯视频、图像及 Hy-MT3 使用已检查 README 的 News 段落作为备用发现源。PixVerse 英文源改为博客路径；Midjourney 支持明确的 Version/Niji 型号标题。
- Niji 博客访问受限时保留异常，不尝试绕过访问限制。腾讯云目录属于可用性/更新证据，不直接当作首发。
- 同篇文章的不同模型家族分别登记；与已有记录匹配时保留原 ID 和最早发现时间。新增候选按近30天有日期、历史、无日期及未来日期分类；不将新 ID 数量等同于新模型数量。
- 采集器不再自动改写权威模型目录。待复核动态可立即呈现，正式版本及 releaseEvidence 仅由明确审核流程入库。
- 改造分支 dry-run 生成临时诊断报告并上传 Actions artifact，便于逐条核对候选；不改写 live JSON。

## 生产采集与证据闭环

定时及 Cloudflare 补采共用 GitHub Actions，不另造发布记录。官方发现、双源正式核验、跨平台线索恢复、近 30 天派生视图和历史关联均保留各自证据与时间语义。自动恢复候选不等于正式首发；明确不满足双源规则时保留待复核。运行健康见 scheduler-health.json / collection-health.json，实际覆盖和固定样本召回见 model-monitor-status.json / release-recall-status.json / system-audit.json。样本命中与全量召回不同；失败退避不修改发布日期或上次成功时间。重建现有派生视图使用 `python3 scripts/preflight.py --repair-digest`，不为通过验证而前移窗口。


## 失效源与待审证据（2026-11-27）

官方入口 403/404 以有界退避处理，备用目录是独立候选，服务集成不等于首次发布。正式证据缺口由 system-audit.json 的 releaseEvidenceReview 列出，可据实际候选链接逐项复核。采集故障不修改发布日期，不将相同公告的翻译或镜像当独立证据。

## 官方文章语言变体回收

Z.ai 的公开研究文章存在带 lang=en 的语言入口。解析器保留同一规范文章 URL 的已发现变体；仅当上次未解析出正文标题、且满足原有退避周期（或解析器版本升级）时，在下次检查尝试一个同源、同规范文章的语言变体。每轮每篇仍只发一次请求，保留实际请求 URL，不因 403 或日期冲突切换入口，不降低正文标题、型号、明确日期与双源正式发布的验证门槛。Niji 403 继续保留失败状态。样本召回改善必须由真实探测确认。
