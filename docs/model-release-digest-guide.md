# 近 30 天模型上新采集规则

用于维护模型上新证据，并由 `site/data/models.json` 生成首页「近 30 天模型上新」视图。跨模块 ID 和字段约定见 [`model-data-contract.md`](model-data-contract.md)。

## 范围

- 只收视频、图像和大语言模型三类正式新型号/新版本。
- 不收智能体工具、语音合成、音频、音乐、产品功能、接口参数、榜单变化或仅有新闻转述的未确认项目。
- 时间范围为采集日往前 30 天，按厂商实际发布日期判断；首页更新日期、新闻转载日期和再次推荐日期不能替代正式发布日期。
- 近期窗口以外的旧型号不为填满列表而补入。无官方新型号时允许结果为空。

## 核验与记录

1. 每日先检查 AI Hub（https://aihub.com/briefing）和已采集的 AIHOT、橘鸦简报，用于尽早发现候选项；这些聚合来源不作为发布日期、型号名称或发布状态的最终证据。
2. 每条记录须有可打开的厂商官网公告、官方模型卡、官方文档或官方仓库链接。优先公告；模型卡更新只有在确认是新型号后才收录。官网若为客户端渲染、自动采集器未读到内容，应打开页面人工核验，不要把零匹配当成没有发布。
3. 逐项核实正式名称、类别、发布日期和可用/权重状态。明确标注「计划开源，尚未发布」等限制，不把计划说成已开放。
4. 同一模型去重；同家公司同批发布多个型号可以在页面上按公司合并展示，数据仍逐型号保留。
5. 不确定或找不到官方证据的内容不进入数据，并在当日日更中说明未核实项。不得推测版本号。
6. 通过 `scripts/build_model_release_digest.py` 重新生成窗口和条目，不直接手改生成文件。

新型号应先在权威模型目录中创建版本，并写入官方证据、正式发布日期和可用状态；同批公告的多个型号逐个绑定自己的版本 ID。模型卡更新可作为证据来源，但若只是能力、接口或功能变化，不创建新模型上新条目。

## 页面语义

页面按公司汇总近期条目，以横向铺满的行卡展示发布日期、类别、型号、中文摘要、可用状态和官方原文链接。它不是完整行业发布记录；缺少条目代表当前采集证据不足，不能据此断言该厂商没有发布。
