# 社媒账号监控数据采集指南

本指南供后续 Codex / 其他 agent 更新 `site/data-v4/social-accounts.json` 时遵循。目标是维护模型厂商和模型聚合平台的**官方社媒账号目录与粉丝数快照**，不是把同名账号或搜索结果当成官方账号。

## 监控范围

- 每个品牌保持 `trackedPlatforms` 定义的 8 个平台位，顺序一致：抖音、B站、小红书、X、Instagram、TikTok、YouTube、Facebook。
- 监控品牌所属的模型/产品官方账号。Google 的 Gemini / Veo 等账号按实际官方社媒账号归属展示；不要只因母公司相同就将不同产品账号合并。
- `updatedAt` 记录这份数据最近一次完整整理日期。每个账号的 `snapshotLabel` 记录该账号粉丝数实际查看日期和平台。

## 官方账号核验

按以下顺序找账号和核实归属：

1. 从品牌官网、官方帮助页、官方 GitHub、官方 Linktree 等入口打开其社媒链接。
2. 若官网没有链接，可在对应平台搜索品牌名、产品名和常见账号名；必须打开候选主页，检查认证标识、简介、官网链接、品牌素材、持续发布的模型宣传内容等证据。搜索结果卡片本身不能证明账号归属。
3. 用另一个官方入口交叉确认。记录具体主页 URL 和可复查的依据；仅凭名称相似、搜索排名或粉丝数不能认定为官方。
4. 平台需登录才能看时，可使用当前已登录浏览器查看公开主页信息。不要记录或导出 Cookie、密码、私信或其他非公开信息，也不要绕过验证码或访问控制。
5. 记录的是厂商/产品用于模型发布、宣传或创作者运营的账号。个人员工号、粉丝号、搬运号不纳入。同一平台若有多个地区或创作者主页，默认记录最贴近模型宣传的主账号；仅在用户明确要求合并时，才用 `relatedPages` 保留其余主页并汇总粉丝数，同时在 `note` 标明受众可能重叠、合计仅供参考。不要静默相加。

### 状态含义

- `verified`：已打开具体主页，且官方来源或主页证据足以确认归属。
- `none`：按品牌名/产品名检查了相应平台，仍未找到可确认的官方主页。填写 `handle: "暂无"`、`url: ""`、`followers: null`、`followersDisplay: "暂无"`；在 `verification` 写明核验日期、检索范围及“未找到可确认主页”，不要写成永久不存在。
- `review`：发现候选账号但归属或主页仍无法确认。保留候选主页链接和不确定原因，粉丝数留空，不能进入已核验账号或粉丝排名。
- 不要把搜索结果页记为 `verified`。只有在确实需要保留检索入口时才使用项目页面支持的 `verified-search`，并清楚说明它是搜索入口，不是官方主页，也不计作已核验主页。

## 粉丝数与时间

- 只记主页明确显示的粉丝/订阅数；不要把获赞、播放量、关注数、作品数混作粉丝数。
- `followers` 存整数原值；`followersDisplay` 存统一格式：小于 10,000 显示整数，例如 `1294`、`548`；达到 10,000 后用“万”，例如 `1.2万`、`25.7万`。禁止显示 `0.0548万` 或混用 M、K、万。
- 平台只显示约数时，按可见值换算并在 `note` 写明“平台显示约数”；不要伪造更精确的位数。看不到粉丝数时用 `followers: null`，并将状态/说明区分为“未读取”或“待核验”，不要写成 0。
- 主页每次核验后，更新该账号 `snapshotLabel`，如 `2026-11-23 · TikTok 公开主页快照`。不得把文件日期伪装成每个平台都已于当天检查。
- `sourceUrl` 尽量链接到能证明官方归属的官网/官方入口；主页自身作为唯一依据时可使用主页 URL，并在 `verification` 解释主页上看到的证据。

## 修改步骤

1. 保留已有品牌和账号记录；先核对 `id`、`name`、`category` 与平台位，不要重排或删掉历史/用户提供的数据。
2. 更新每个平台账号对象的 `handle`、`url`、`status`、`verification`、`sourceUrl`、`followers`、`followersDisplay`、`snapshotLabel` 和必要的 `note`。
3. 整理完一批后更新顶层 `updatedAt`；只有确实完成该轮整理时才改日期。
4. 验证 JSON：

   ```bash
   python3 -m json.tool site/data-v4/social-accounts.json >/dev/null
   ```

5. 再检查每个品牌是否正好有 8 个不同平台位、粉丝数字段是否自洽，以及 `none` / `review` 是否误入粉丝排名。若页面展示或排序逻辑改变，按项目 `AGENTS.md` 中的要求完成相应验证。

## 向用户汇报

更新完成时说明：本轮实际打开核验的平台主页数量、按平台的快照日期、无法读取或待核验的账号，以及尚未检查的平台。不要只说“已全网核实”；不要把搜索页、搜索结果或未经核验的数据汇报成已完成。

当前没有为社媒粉丝数配置自动采集器；静态数据中的历史快照不会随每日其他采集任务自动刷新。
