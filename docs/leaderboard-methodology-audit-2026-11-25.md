# 创作者能力榜方法审计（2026-11-25）

## 结论

当前 v4 不能称为权威综合榜。它能复算公开快照，但模型资格、快照来源链、任务口径和产品可用性尚未满足独立评测的要求。展示的小数和“正式名次”只说明旧代码通过了自己的阈值，不能证明“创作者更应该用哪个模型”。

此前的三位评审重点检查了公式实现、身份锚点和音频任务标记，没有审核公开榜单快照的发布链、模型是否是创作者能直接使用的正式版本，以及后训练衍生端点是否重复占位。因此“多位专家审核通过”说得过头了；审核范围不足以背书当前榜单结论。

本次按用户要求，将多模态理解从综合榜删除。历史快照继续保留，不删除历史数据。

## 2026-11-25 展示口径修正

上一版把 v4 跨榜试算与官方原榜顺序混在一个表格：分数排序产生“暂估序”，而通过旧公式门槛的行另有“正式序”，两种序号可能彼此冲突。音乐因器乐/人声池不兼容被整类隐藏，TTS 又只接入了开放权重子榜。

前台现改为五类来源原榜参考视图：图像用 Arena 文生图；视频分 AA 有声文生与有声图生两个独立任务页签，并按基础模型资格隐藏 H3 生态衍生产品和同家族重复版本；音乐显示 AA 含人声榜，器乐榜作为独立任务；语音使用 AA 全量 Provider Voice；编程保留 Arena Code。每个视频任务从各自原榜前 20 名筛选，最多显示 10 个候选，保留原榜序号，所以可能显示 #11、#14 等名次。旧 v4 合成试算继续留在生成数据中供审计，但不再作为前台名次。

MAI-Image-2.7 经 Microsoft 官方模型卡、Microsoft Foundry 与发布页确认是真实模型，2026-11-17 发布、处于公共预览；Arena 快照中的文生图第 4 名来自其原榜，不是本项目合榜算法产生。

本次复核还发现 AA 视频源快照的 Seedance 2.5 与 Hyperflow H3 在同一天被抄反了名次；已根据 AA 当时可见页面刷新为 Hyperflow #4、Seedance 2.5 #5，并记录来源核对时间。Boreal-H3 是另一个有声 I2V 池的条目，已从 T2V 筛选记录移除。Pruna 官方确认 P-Video-2-Pro 基于 MiniMax H3，现与其他 H3 衍生端点一样从基础模型主榜排除。模型库也已不再显示历史跨榜试算分，只保留逐版本的来源榜名次和可查原榜数量。

用户指出 Wan 3.0 排名靠前但身边创作者主要使用 Seedance 2.5。该观察揭示了“输出偏好”与“实际采用”是两个问题：AA 视频榜用验证过的内部评审者做盲测偏好比较，不是使用份额调查。2026-11-25 快照里，T2V Wan #1（95% CI 1163–1187）、Seedance 2.5 #5（1142–1166），分数区间与原榜名次范围重叠；I2V Seedance 2.5 #2（1144–1172）、MAGI-2 #1（1149–1177），区间和名次范围也重叠。不能把这些相邻次序表述成稳定胜负，也不能从榜单推出创作者采用率。前台现已拆出有声文生/图生两个任务页签，并把采用率边界直接写在榜单说明中。

## 本地数据审计发现

1. **评测机构与快照发布者曾被混为一谈。** `site/data/reference-rankings.json` 的快照发布者是 FAI.Fashion，原始榜单链接才指向 Arena 或 Artificial Analysis；部分 Arena 榜由 `site/data/maomu-rankings.json` 的猫目快照提供。此前页面有评测机构链接，但没有在榜单主视图突出“第三方整理快照”，降低了来源透明度。
2. **视频衍生端点混入主榜。** Artificial Analysis 官方方法将原生标准端点和 Modified 端点分开；Modified 可涉及蒸馏、参数暴露变化或输出质量变化，并可能默认隐藏。旧输入快照没有把这类资格充分落实为主榜排除规则，导致 H3 基础模型和多个基于 H3 的第三方端点一起出现。它们不一定是“假的”，但若目标是比较基础模型，就不能当作多个互相独立的基础模型。本轮又核对到 Pruna 官方明确 P-Video-2-Pro 基于 MiniMax H3，现已纳入同一排除规则。
3. **视频来源不符合“只看有声”条件。** Arena 官方视频说明称，并非所有模型都支持音频，且每次随机匹配的音频输出可能不同；其通用 T2V/I2V 榜不是纯有声评测。不能因为榜单叫视频 Arena，就把它当成有声视频任务数据。
4. **图片表格排序曾让分数与名次观感冲突。** v4 原先把达到旧公式门槛的行全部排在单源暂定行之前，而不是按分数一起展示；因此 GPT Image 2.6 的试算点分高于 MAI-Image-2.7，却显示在其后。当前前台不再展示这些跨榜试算，改为直接显示 Arena 文生图来源名次；这解决了两套序号争抢主表的问题，但不能把 Arena 偏好分说成市场采用率或客观质量。
5. **音乐没有可用综合分，却按名称显示成一列。** 器乐榜中 Suno v6 原榜为第 1，但人声来源只有不完整的二手记录；v4 没有足够依据生成音乐总分。当前主表改为只读 AA 含人声原榜前十；器乐榜是另一任务池，不伪装成跨任务音乐总榜。
6. **TTS 误用了开放权重筛选。** 旧快照只保存 Artificial Analysis Provider Voice 的 Open Weights 子榜，故 ElevenLabs 不在候选内。这是来源筛选错误，不是 ElevenLabs 能力低。当前主表改用全量 Provider Voice 榜，Eleven v4 Turbo 与 Eleven v4 排在前两位；这仍是单来源证据，不代表语音克隆或所有语言任务。

这些问题说明当前榜失真主要来自资格和呈现层。它们并不能证明 Artificial Analysis 或 Arena 在造假。Artificial Analysis 使用经验证的内部评审者做盲比，也明确披露 Standard/Modified 端点；Arena 的社区对战更贴近公开用户偏好，并公开了计算包。但二者的评审人群、任务抽样、产品资格和评测目标不同，不能把分数直接平均。

## 公开来源的适用边界

- **Arena**：适合回答“社区用户在该 Arena 任务分布下更喜欢哪个输出”。官方提供 Arena-Rank 开源实现和部分公开数据；公开榜正式名称另有供应商发布资格门槛。它不是创作者特定任务的客观质量测量。视频榜还存在音频覆盖不齐的问题。
- **Artificial Analysis**：图像和视频方法采用偏好比较，并以 Bradley–Terry/Elo 估计；视频把有声/无声、文生/图生、编辑放在各自任务池。其 Standard/Modified 分类正好能帮助定义端点资格，但快照必须应用正确筛选，并确认模型身份与公开可用性。
- **AIHOT**：其难度校正、同类基准去重、缺测不补分和来源状态分层适用于客观基准成绩汇总；但它不能把主观图像/视频/音乐偏好自动变成客观正确率，也不能替代创作者任务权重的选择。
- **已有研究**：NeurIPS 2025 的《The Leaderboard Illusion》基于 2024–2025 年数据，指出私有候选测试、选择性撤榜和样本不均衡可能影响社区榜；这不能直接证明当前 Arena 政策下仍发生同样现象。2026-11 的一篇预印本进一步展示，开放提示、策略投票和候选投放会影响 Bradley–Terry 类排名；它证明的是可能的攻击面，不是任何具体榜单正在被操纵。

## 建议的 v5：自有创作者盲测为主，外部榜单为对照

### 1. 先定候选资格，不从榜单名次反推资格

- 主榜只收录本期有官方产品/API/权重、创作者确实可用的明确版本，并记录地区、访问方式、发布日期、API/产品地址、计价与授权。
- 预览版、研究别名、已撤回模型进入“观察区”，不参加正式综合名次。
- 同一底座的第三方后训练端点、蒸馏端点、代运营平台模型不和底座争基础模型名次；它们可以另列为“创作产品/衍生模型”，保留自己的工具价值。
- 每次评测固定参赛名单和退赛规则，参赛方不能反复提交大量候选后只保留最高分版本。

### 2. 为不同任务用不同测量，不强求一把公式

- **图片、视频、音乐、语音**等没有唯一客观答案的生成任务：使用固定任务集上的盲测两两比较。左右位置随机，输出隐藏厂商与型号；同提示、同输入素材、同分辨率/时长/配置；重复随机种子估计生成波动。视频音频榜要求提示中明确有声，并逐条确认输出含有效音轨。
- **编程**：以可执行的隐藏测试、仓库任务完成率和回归测试为主；Arena Code 的偏好分只作为用户体验对照，不能替代程序是否通过测试。
- 对创作结果可另记可解释维度，例如指令遵循、视觉/动作连续性、音画同步、文字准确、音乐结构、语音可懂度。单一总分不能掩盖“视频好看但没有声音”这类任务失败。

### 3. 用可复核的统计模型，并把样本误差算进去

- 生成偏好任务使用带提示类别和评审者效应的 Bradley–Terry/Thurstone 混合模型；对同一提示、同一评审的相关判断做分组处理。不能把每一票当成完全独立样本。
- 结果按提示集和评审者做分层/簇自助法，给出模型能力区间、相对胜率区间和名次分布。位置偏差、重复提示、低质量投票、并列判断和不同提示簇都要进入审计。
- 样本数由先导实验估计方差后，按目标区间宽度与 Top-K 稳定性做功效分析；不把“至少 20 个锚点”当成万能科学门槛。可以预先约定一个产品精度目标，但要标明那是本项目的决策标准。
- 差异区间高度重叠时显示同一档/无法区分，不用小数点强行排先后。模型增加或退赛后要重算不确定性，并保留当期冻结名单。

### 4. 合成单一类别榜时，权重代表用户用途，不代表普遍真理

同一类别的子任务先独立估计并标准化到冻结参考集合，再按明确的创作者工作流权重合成：

`类别指数(model) = Σ 任务权重 × 标准化任务分(model)`

图片至少区分文生图/编辑；视频区分有声文生/图生；音乐区分器乐/人声；语音区分旁白/对白/克隆等真实创作任务。初版可对子任务等权，但必须标注“产品权重，非统计事实”；更合适的是按用户的实际使用频率设置并公开。缺测任务不填平均值，也不按零分惩罚；若覆盖不够，显示“证据不足”而不排名。

### 5. 对照榜保留原分，不直接当成另一票

Arena、AA 和其他榜单在页面给出原始名次、分数、票数/样本、区间、快照日期、任务版本和原始链接。只有拿到同任务原始比较数据，或通过预注册的共同盲测样本完成校准，才考虑合并不同来源。单凭相似模型的名次、Elo 刻度或大量重叠名称都不足以证明可比。

## 建议实施顺序

1. 将现有 v4 保留为历史试算、不再在前台显示为综合名次。当前主表直读各来源原榜前十并公开资格筛选、分数区间与快照日期。
2. 先定义参赛资格和创作者任务集，尤其核验图片变体、H3 衍生端点、全量 TTS、音乐器乐/人声、视频音轨。
3. 做一轮小规模盲测先导，估计每类任务所需样本数、评审一致性和费用，再决定是否扩大到完整榜。
4. 发布前让评测专家审核任务集、身份映射、统计模型和误差报告；审核结果需写明审了什么、没审什么。

完整盲测会调用商业模型/API并投入真实评审时间，可能发生费用；现阶段只完成方法设计和公开资料核对，未开始调用模型或众包评审。
